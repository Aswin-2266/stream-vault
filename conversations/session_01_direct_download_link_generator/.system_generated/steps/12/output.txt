When working with Telegram bots, you will naturally hit a strict wall: **the official Telegram Bot API restricts file downloads via `getFile` to 20 MB** (and uploads to 50 MB)[1]. If you try to download a file larger than 20 MB using standard Bot API methods, Telegram will return a `Bad Request: file is too big` error[2].

To bypass this 20 MB limit using Python and **Pyrogram**, you have two main approaches: **switching your bot to the MTProto Client API** or **setting up a Local Bot API Server**[3].

---

### Solution 1: Use Pyrogram as an MTProto Client (Recommended)
By default, Pyrogram can act as a **Bot user via MTProto** instead of using the standard HTTP Bot API. When you log in with a `bot_token` using Pyrogram's `Client`, it communicates directly with Telegram's MTProto protocol rather than going through the Bot API endpoints[4][5]. 

This completely removes the 20MB download limit, allowing you to download files **up to 2 GB**[4][5].

#### How to implement it:
1. Get your `api_id` and `api_hash` from [my.telegram.org](https://my.telegram.org/)[6].
2. Initialize Pyrogram using your `bot_token`[6].

```python
from pyrogram import Client, filters

# Initialize the Pyrogram client with your bot token
app = Client(
    "my_bot_session",
    api_id=YOUR_API_ID,
    api_hash="YOUR_API_HASH",
    bot_token="YOUR_BOT_TOKEN"
)

@app.on_message(filters.document | filters.video | filters.audio)
async def download_large_file(client, message):
    file = message.document or message.video or message.audio
    
    print(f"File size: {file.file_size} bytes. Downloading...")
    
    # download() uses MTProto under the hood, bypassing the 20MB Bot API limit
    file_path = await message.download(
        file_name="downloads/",
        progress=progress_callback
    )
    
    print(f"Successfully downloaded to: {file_path}")

def progress_callback(current, total):
    print(f"Downloaded {current} of {total} bytes ({(current/total)*100:.2f}%)")

app.run()
```

*Note: Pyrogram handles all the MTProto data center chunking automatically, allowing seamless downloading of heavy files sent to your bot.*

---

### Solution 2: Use a Local Telegram Bot API Server
If you strictly want to keep using standard Bot API code (e.g., libraries like `aiogram`, `pyTelegramBotAPI`, or raw requests), you can host your own instance of Telegram's official **Local Bot API Server**[7][8].

* **How it works:** Telegram provides the source code for their Bot API server[9]. Running it locally overrides the cloud limits, allowing your bot to download and upload files **up to 2 GB**[8].
* **How to run it (via Docker):**
  The easiest way is using a pre-built Docker image (like `aiogram/telegram-bot-api`)[3][9]:
  ```bash
  docker run -d \
    -p 8081:8081 \
    -e TELEGRAM_API_ID=YOUR_API_ID \
    -e TELEGRAM_API_HASH=YOUR_API_HASH \
    aiogram/telegram-bot-api
  ```
* **Configuring Pyrogram/Bot to use it:**
  If you still want to use Pyrogram pointing to your local server instead of Telegram's public cloud API, configure the `base_url`:
  ```python
  app = Client(
      "my_bot_session",
      api_id=YOUR_API_ID,
      api_hash="YOUR_API_HASH",
      bot_token="YOUR_BOT_TOKEN",
      base_url="http://localhost:8081"  # Points to your local Bot API server
  )
  ```

### Summary
* If you want a quick fix in Python without running extra server infrastructure, **switch to Pyrogram's MTProto client mode** (Solution 1)[4][5]. 
* If your architecture heavily relies on traditional Bot API webhook structures or standard HTTP bot frameworks, spin up a **Local Bot API Server** using Docker (Solution 2)[3][9][8].
